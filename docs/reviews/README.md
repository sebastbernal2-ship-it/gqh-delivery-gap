# Reviews

Everything the team found wrong with the idea or the plan goes here. This folder is first class,
not an afterthought.

Two kinds of file:

- `YYYY-MM-DD-<topic>.md` for a written critique. Copy `TEMPLATE.md` and fill it in.
- A line in `docs/03-decisions.md` once the critique settles into a decision.

## Why this matters for the score

The rubric scores Economic Foundation and creativity, and it caps the evidence score for anything
that looks fitted. A review that kills a weak leg early is worth more than a backtest that survives
by accident. Write the objection down, with evidence, before the run that would have settled it.

## Rules

1. Attack the mechanism first, then the measurement, then the code. That is the order that matters.
2. Every objection names the evidence that would settle it.
3. Every objection says what it replaces, or it is a question, not a review.
4. Do not edit someone else's review. File your own, or answer it in yours.
