# Style

The single owner of how we write here. It has two halves: how we write about evidence, and how the
prose reads.

Owner: Vishnu via his documentation agent. Initial conventions captured from the user's request;
strategy approval and the note's results remain with their existing owners.

## How we write about evidence

- Lead with the economic question and measured answer, not a list of tools.
- Use plain, specific language. Explain who bears a risk and the cash-flow channel.
- Separate user-reported access, documentation verification, tested downloads and measured results.
- Label proposals, exploratory studies and archived work. Never imply code exists because its
  directory appears in a design document.
- Distinguish expected changes from surprises. Identify the earlier expectation, same target
  period, availability time and metric units.
- Report missing data, field breaks, correlated events and negative findings alongside positives.
- Say "candidate mechanism" before validation; avoid "the market ignores this" without evidence.
- Do not equate long histories with independent observations, beta neutrality with tail immunity,
  schema validation with semantic truth, or strict typing with exact floating-point arithmetic.
- Describe the long-history core separately from short-history compute/crypto extensions.
- Every strategy performance number must trace to a generated results artifact. Source facts
  trace to original documents or the source audit, not a generated backtest artifact.
- Cite exact source passages and dates near claims; keep detailed receipts in their owner document.
- One section per writer; link to owner facts rather than maintaining duplicate competing summaries.
- Capture why thinking changed. Do not rewrite the history as if the final method was obvious.
- Follow docs/brief.md for submission format; this file does not redefine competition rules.

## How the prose reads

1. **Short sentences. Plain words.** If a sentence needs a second comma to survive, split it.
2. **One idea per sentence.** A reader who has to re-read a sentence has stopped reading.
3. **Active voice.** Name who does what.
4. **No filler.** Cut "very", "quite", "in order to", "it is worth noting that", "basically".
5. **Numbers point at a file.** Never write a number you cannot trace to `results/`.
6. **Claim, then evidence.** State the thing, then the reason it is true.
7. **Say what failed.** A rejected line of work, with the reason, is worth more than an extra result.
8. **No unearned confidence.** "We measured" beats "clearly". "In our sample" beats "always".
9. **No hedging in place of a decision.** If we do not know, say what we would need to know it.

## Mechanics

- Spell out a term once, then use it consistently. One meaning per term.
- Define a symbol at first use.
- Tables for three or more comparable numbers.
- A figure earns its space or it goes.

## For agents

Agents write in the same voice. No flourishes, no "let us dive in", no restating the prompt.
Short, direct, and specific.
